# R5 — GGUF quant format mismatched to target ISA runtime-repack path

> x86→Arm/Graviton migration template · kind: `probe` · confidence: medium · expected gain (estimate): 1.2–2×

## Anti-pattern

llama.cpp runtime-repacks Q4_0 weights into aarch64-optimized layouts when dotprod/i8mm are present; K-quants skip that fast path, and Q4_0 on a host WITHOUT dotprod cannot repack at all. Either direction leaves tokens/sec on the table for the silicon actually being used.

## Before → after

```bash
llama-cli -m model-Q4_K_M.gguf           # K-quant: no runtime repack on this host
```

```bash
llama-cli -m model-Q4_0.gguf             # Q4_0 engages the dotprod/i8mm repack path
```

## Fix

Propose the quant variant matched to the detected ISA (Q4_0 to engage the repack path on dotprod/i8mm hosts; a K-quant where repack cannot engage) and A/B both GGUFs through the reproduce gate.

## Expected gain

1.2–2× — ESTIMATE from llama.cpp Arm build documentation; quant swaps also shift quality, so the fix always states the perplexity trade and the gate measures speed only.

> Estimates are for planning order only. Only Armsmith's reproduce gate (median-of-N · MAD noise band · output-hash equality) can claim a result.
