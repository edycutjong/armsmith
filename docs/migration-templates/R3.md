# R3 — NumPy/SciPy linked against reference BLAS instead of an optimized backend

> x86→Arm/Graviton migration template · kind: `probe` · confidence: high · expected gain (estimate): 1.5–5×

## Anti-pattern

numpy.show_config() output shows no optimized BLAS (OpenBLAS / BLIS / Arm Performance Libraries / Accelerate); matrix math falls back to the netlib reference implementation, which is dramatically slower on Neoverse cores and typical of distro python + source-built numpy on arm64.

## Before → after

```bash
pip install --no-binary numpy numpy    # builds against whatever BLAS is on the box
```

```bash
pip install --only-binary=:all: numpy  # manylinux aarch64 wheel, OpenBLAS bundled
```

## Fix

Reinstall NumPy/SciPy from official PyPI manylinux aarch64 wheels (which bundle OpenBLAS), or rebuild against OpenBLAS/ArmPL; pin the wheel in the lockfile so the fix sticks.

## Expected gain

1.5–5× — ESTIMATE — reference-BLAS penalties are workload-dependent (largest for GEMM-heavy embed paths). Only gate-measured deltas are ever claimed.
