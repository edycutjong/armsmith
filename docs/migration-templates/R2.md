# R2 — Native build without -mcpu/-march (generic aarch64 codegen)

> x86→Arm/Graviton migration template · kind: `probe` · confidence: medium · expected gain (estimate): 1.1–1.5×

## Anti-pattern

Compiler invocations in the build log compile C/C++ sources with optimization flags but no -mcpu=/-march= target, so GCC/Clang emit lowest-common-denominator ARMv8.0 code and never use dotprod/i8mm/SVE even when the host CPU reports them.

## Before → after

```bash
CFLAGS="-O3"
```

```bash
CFLAGS="-O3 -mcpu=native"      # or, for portable builds: -march=armv8.2-a+dotprod+i8mm
```

## Fix

Inject -mcpu=native (preferred on native builds) or an explicit -march=armv8.2-a+dotprod(+i8mm) matching the detected ISA features into CFLAGS/CXXFLAGS for the native extension build.

1.1–1.5× — ESTIMATE from compiler documentation; real gain depends on how hot the native extension is. The reproduce gate decides.
