# R6 — Thread oversubscription (threads x workers > vCPUs)

> x86→Arm/Graviton migration template · kind: `probe` · confidence: high · expected gain (estimate): 1.2–3×

## Anti-pattern

Each worker process spawns a full complement of OpenMP/BLAS threads (the default is one per vCPU when OMP_NUM_THREADS is unset), so N workers x nproc threads thrash a box with only nproc vCPUs — context-switch storms and cache eviction instead of throughput.

## Fix

Set OMP_NUM_THREADS (and sibling knobs like OPENBLAS_NUM_THREADS) to floor(nproc / workers), or reduce worker count, so total runnable threads match the vCPU budget.
