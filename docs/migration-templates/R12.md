# R12 — CI publishes amd64-only images (no arm64 in the build matrix)

> x86→Arm/Graviton migration template · kind: `static` · confidence: high · expected gain (estimate): 1–1×

## Anti-pattern

The GitHub Actions workflow builds/pushes Docker images without an arm64 platform (docker/build-push-action without platforms including linux/arm64, or a plain docker build on an x86 runner) — every Arm consumer of the published image is silently forced into emulation (R1 on their side).

## Before → after

```yaml
- uses: docker/build-push-action@v6
  with:
    platforms: linux/amd64
```

```yaml
- uses: docker/build-push-action@v6
  with:
    platforms: linux/amd64,linux/arm64
```

## Fix

Add platforms linux/amd64,linux/arm64 to the buildx step (with setup-qemu/setup-buildx), or build natively on the free public-repo arm64 runners (labels ubuntu-24.04-arm / ubuntu-22.04-arm, verified in crawl/clean/sdk_github-arm64-runners.md).

## Expected gain

1–1× — Ecosystem/correctness fix: no local speedup is claimed (range pinned to 1.0x). The runtime gain lands on consumers who stop pulling emulated images — that side is R1's measurement.

> Estimates are for planning order only. Only Armsmith's reproduce gate (median-of-N · MAD noise band · output-hash equality) can claim a result.
