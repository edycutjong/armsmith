# R11 — Missing THP/allocator tuning for large-model RSS

> x86→Arm/Graviton migration template · kind: `probe` · confidence: medium · expected gain (estimate): 1.05–1.3×

## Anti-pattern

Transparent hugepages disabled ([never]) and/or no modern allocator (tcmalloc/jemalloc) mapped into the serving process: large model heaps then pay 4K-page TLB pressure and glibc-malloc fragmentation — a steady tax on multi-GB RSS inference workloads.

## Fix

Set THP to madvise (kernel admin guide), and/or LD_PRELOAD libjemalloc/libtcmalloc for the serving process; both knobs are environment-level (no code change) and A/B-able through the gate.

## Expected gain

1.05–1.3× — ESTIMATE — allocator/THP effects are workload- and RSS-dependent and often small; in-band results are reported as "no change" and dropped.
